# ULC 실매매 차트

계좌 체결 기록 + 엔진 로그에서 상한가(ULC) 매매를 찾아, 키움 차트 API로 봉을 받아 HTML로 그린다.
**조회 API만 쓰고 주문은 내지 않는다.** 실계좌 자격증명(`backend/.env`)이 필요하다.

## 실행

```bash
cd backend && uv run python ../.claude/skills/ulc-trade-chart/ulc_trade_chart.py
```

옵션:
- `--since 2026-10-01` / `--until 2026-10-15`: 기간(포함)
- `--code 001520`: 종목만(여러 번 가능)
- `--account real`: 계좌 id(기본 `real`). 체결 파일은 `state.{계좌}.trades.json`
- `--out <path>`: 출력(기본 `research/ulc_trades/index.html`, git 미추적)
- `--refresh`: 봉 캐시(`backend/backtest_data/trade_chart/`, candle-trade-chart와 공유) 무시

Windows 콘솔에서 한글 출력이 깨지면 `PYTHONIOENCODING=utf-8`을 앞에 붙인다.

## 만든 뒤

1. 내장 브라우저로 `file:///<repo>/research/ulc_trades/index.html`을 열고 콘솔 오류가 없는지, 차트가 그려졌는지 확인한다.
   미리보기 패널은 처음에 폭 0으로 그릴 때가 있어 템플릿이 ResizeObserver로 범위를 다시 맞춘다.
   파일이 ~550KB를 넘으면 패널이 못 여니, 커지면 봉 수를 줄인다(일봉은 종목별 95봉 앞부터, 전일 3분봉은 60개만).
2. `SendUserFile`(display: render)로 HTML을 보낸다.
3. 요약: 건수, 승/패, 실현 손익 합계(수수료·세금 제외), 손절 종목, 주의 사항(미청산·수동 매도).

## 판정 규칙 (스크립트 동작)

- 체결 기록의 주문 태그(`strategy`·`reason`·`ctx`, 2026-10-18 서버 변경 이후 체결)가 있으면 그것을 먼저 쓰고, 없는 예전 체결만 로그로 판정한다. 로그가 지워져도 태그가 있는 매매는 다시 만들 수 있다(카드의 엔진 로그 목록만 빠진다).
- 로그는 넘겨 쓴 파일까지 오래된 순서로 읽는다(`events.log.10` … `.1`, `events.log`; 서버가 10MB마다 넘겨 쓰고 10개까지 보관). 그보다 오래된 로그는 서버가 지워 차트로 다시 만들 수 없다.
- **ULC 매매** = 그날 그 종목에 엔진 메시지 `자동매매 시작 (X=…, Z=…)`가 있고 체결이 있는 경우.
  대금 양봉·구간 매매(`candle_trade` 이벤트)와 순수 수동매매는 이 메시지가 없어 자동 제외.
- 체결은 주문번호(`id`의 두 번째 칸)로 묶고, 엔진 메시지 순서대로 사유를 붙인다:
  매수 `N차 매수` → `1차/2차/3차`, 매도 `익절`/`트레일링 스탑`/`손절:`. 남는 주문은 `수동`.
- 매수 수량 = 매도 수량이면 청산(손익 산정), 아니면 `미청산`(그날 이후 매도는 반영 안 함).
- 체결 `time`은 차트 epoch(KST 벽시계를 UTC로 둔 값)라 봉 시각과 바로 비교된다. 3분봉 시각은 봉 시작 기준.
- **계좌 체결 채우기**: Bach 체결 기록은 서버가 켜져 있을 때 받은 체결 통지만 적는다. 그래서 매매일마다 계좌 주문체결내역(`kt00007`, 조회 전용)을 함께 보고, 기록에 없는 주문(서버가 꺼져 있을 때 HTS·모바일로 낸 주문 등)을 채운다 — 시각은 주문 시각, 가격은 주문별 체결 단가(원 미만 절사). HTS·모바일 주문은 `수동(영웅문S#)`처럼 경로를 표시한다. 지난 날 조회는 캐시(`*_orders.json`), 조회 실패 시 Bach 기록만 쓰고 경고를 출력한다.
- **여러 날**: 그날 청산되지 않은 매매는 다음 거래일들을 따라가며 보유가 0이 될 때까지 한 카드로 묶는다(그 종목의 다음 ULC 매매일 전까지). 3분봉은 날짜 버튼으로 이동, 결과가 사람 매도로만 끝났으면 `수동 청산`.
- **설정**: 카드 머리에 그 매매를 시작할 때의 청산 설정(손절·익절·트레일링 등). 주문 태그 `ctx.exit`, 없으면 `자동매매 시작` 로그의 `config` 필드(2026-10-18 이후). 그 전 매매는 "기록 없음".
- **수동 전환**: 상태 전환 로그 `AUTO_TRADING → MANUAL_TRADING`(2026-10-18 이전) / `→ IDLE`·`→ MANUAL`(이후, MANUAL = 수동 매매 목록으로 옮김) 중 그 시점에 보유 수량이 남은 것만(PUSH 중단, 손절 기준 인계, 재시작 인계, 엔진 종료 뒤 잔량 등 — ENGINE_DONE은 마지막 매도 체결이 늦게 찍힐 수 있어 60초 여유). 차트에 ■ `수동 전환 · 원인` 마커 + 그 뒤 옅은 주황 배경. 로그와 함께 서버의 인계 기록(`backend/state.{계좌}.events.json`, 2026-10-18 이후)도 읽어 합치므로 로그가 지워져도 남는다.
- 3분봉은 정규장(≤15:27 시작 봉)만, 앞에 직전 거래일 정규장 3분봉 60개를 붙여 MA60을 09:00부터 잇는다.

## 차트 표현 (Bach 프런트와 동일)

- 체결 건마다 캔들 안 체결가 위치에 ✕ (`frontend/src/tradeCrossPrimitive.js` 이식, 매수 `#d32f2f`/매도 `#1565c0`)
- 봉 위/아래 화살표 마커 `B 1차`, `S 익절` (일봉은 `B 수량 · 평단`)
- MA5 `#2962FF` / MA10 `#FF4FA3` / MA20 `#FF9800` / MA60 `#26A65B` (`frontend/src/indicators.js` `MA_LINES`)
- 이 규칙은 공통 `../_trade_chart_common/chart.js`에 있다. Bach 쪽 색·마커 규칙이 바뀌면 거기만 고친다.

## 파일

- `ulc_trade_chart.py`: ULC 매매 판정·손익·카드 데이터
- `template.html`: 목록·카드·차트 구성. `/*__CHART_CSS__*/`·`/*__CHART_JS__*/`·`__DATA__` 자리를 채운다
- 공통(`../_trade_chart_common/`, candle-trade-chart와 공유): `common.py`(키움 봉 조회·캐시, 체결 묶기,
  HTML 조립), `chart.css`, `chart.js`(✕·이평선·차트 생성·목록 이동). 두 스킬에 함께 쓰이니 바꾸면 둘 다 다시 만들어 확인한다.
